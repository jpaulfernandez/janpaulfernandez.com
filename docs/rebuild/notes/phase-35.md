## 35.4
- `src/scripts/gallery.ts` `initDensity(grid)`: levels 3/5/7 and 4/6/8/12 behind `matchMedia('(min-width: 48rem)')`; writes only `--cols` and each img's `sizes` (`(100/n).toFixed(1)vw`); `gallery-cols` in localStorage inside try/catch, accepted only if the current breakpoint offers it, re-resolved on the breakpoint `change`.
- Readout is `{n} per row` in an `aria-live="polite"` span; buttons carry `aria-keyshortcuts` and a `title` naming the key. Keys ignore modifier chords (so browser ⌘−/⌘= zoom is untouched), form fields, and an open dialog. ⌘/Ctrl+wheel is bound on the grid only, `preventDefault` only with the modifier; 60 deltaY units per step.
- Verified in the browser pane: at 1280 buttons step 6→8→12 (− disabled at 12) and back to 4 (+ disabled); real `-`/`=` key presses step 6→8→6; ctrl+wheel 30+40 = one step, meta+wheel −100 = one step back, plain wheel not prevented; synthetic two-pointer pinch steps a level per 25% and the following click is swallowed (no viewer); level survives reload. At 375 (mobile preset): default 3, stored `6` rejected, 3→5→7 (− disabled) and back.
- No-JS (scripts stripped from a copy of the built page, headless Chrome at 1280): no control, grid at 6. Headless Chrome cannot go below ~500px wide, so the 375 no-JS check rests on the CSS default (`--cols: 3` below 48rem), which the pane showed at 375.

## 35.5
- `Lightbox.astro` is markup + CSS only: white `paper` ground and `::backdrop`, `100dvw`/`100dvh`, `html:has(dialog[open]) { overflow: hidden }`, hairline mono `ink-900` buttons, caption `ink-600`, link `red-700` reading "from {Set} →", counter `ink-400` `aria-live`. The dark scrim, the transition and the open animation are gone. `touch-action: none` on `.lightbox-image-wrap` only; img `draggable="false"`.
- `initViewer()` in `gallery.ts`: triggers collected once; preloads both neighbours; arrows / buttons / swipe (>50px, horizontal-dominant, only at 1×); close via Esc (native cancel), button, or a click on the empty ground around the photo (dialog, inner, or stage — not the image), swallowed after any swipe/pan/pinch/double-tap. Pinch 1–4× anchored on the finger midpoint; one finger pans when zoomed, clamped to the stage; double-tap/double-click (300 ms, 30 px) toggles 1×↔2× at the point; zoom resets on every photo change. Focus: close button on open; on `close` the thumbnail of the photo you ended on gets focus + `scrollIntoView({block:'nearest'})`.
- Bundle: Astro/Vite emits `/_astro/gallery.*.js` as a shared chunk (4,457 B raw / 2,080 B gzip) plus a page entry of 159 B gz (index) / 118 B gz (set pages). Because both pages import one module, the shared chunk holds both exports, so **set pages also download `initDensity` (unused, never called)**. The DoD's "set pages ship the viewer only" would need two modules, which the phase forbids ("do not split gallery.ts"); the budget (≤6 KB) is met either way. Flagged for Paul/reviewer.
- Verified in the pane at 375 (mobile emulation): open from thumbnail (focus on ✕, counter `4 / 95`, link "from BINI: Asiya →"), arrows and buttons wrap (1 ↔ 95), synthetic touch swipe left/right navigates, vertical drag does not, click after a swipe does not close, click on the stage closes; pinch → `scale(2)` then clamps at `scale(4)`, remaining finger pans, swipe while zoomed pans instead of navigating, next photo resets the transform, double-click zooms to 2× at the point and again back to 1×. Real-key pass: Tab to thumbnail 2, Enter opens on 2/95, → → ← lands on 3/95, Esc closes, focus is on thumbnail 3 (not the opener). Note: the pane's `close` event only fires while the pane is rendering (it is tied to a frame); with the pane hidden, programmatic closes did not fire it. Not a site bug, but it is why one scripted focus check read wrong.
